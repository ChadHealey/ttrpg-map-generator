# Proposed ADR — Quota-first v3 macro geography and versioned realization

- **Status:** Proposed; no family selected
- **Date:** 2026-09-06
- **Decision owners:** Project maintainers
- **Supersedes:** None now; would supersede ADR-0029's generation-family adoption decision if accepted
- **Superseded by:** None

## Context

The [M2 product proof](../../milestone-2-atlas-proof.md) requires attractive, deterministic,
accepted geography that survives save/reopen/reroll/export. [ADR-0029](../../adr/0029-separated-macro-landmass-field.md)
is accepted and remains unchanged. The [issue-164 successor proposal](../issue-164/proposed-adr.md)
and later private investigations have not selected production v3.

[Issue-179 r2](../issue-179/visual-review-r2.md) improves broad anatomy and earns four provisional
ordinary passes, but the balanced control still fails R3. Its zero-contour certificate and private
grid are not production classification or persistence contracts. A quota-first field also changes
water from classification-only intent to an upstream geometric input. That durable compatibility
change needs an explicit decision before implementation.

This unnumbered, issue-owned proposal records a candidate boundary. It does not accept the family,
change the project plan, confer human image acceptance or alter accepted worlds.

## Decision drivers

- Preserve all accepted v1/v2 data and generator-free reopen, including user-accepted v2 records
  regardless of the subsequent rejection of v2 candidate evidence.
- Keep spherical area, explicit roles, bounded placement and deterministic no-proposal behavior
  inspectable; do not repair failures through rendering or semantic relabeling.
- Make control ownership, threshold/profile realization, versions and stream scopes truthful.
- Demonstrate human visual quality and macOS/Linux reproducibility before default adoption.

## Options considered

### Option A — Continue current production while investigating

Keep current dispatch and all accepted records unchanged. Publish the proposed boundary and run
only separately authorized bounded probes. This is the current state and remains valid if the
private family is rejected.

### Option B — Select a quota-first spherical envelope successor

After the visual/ADR gates, introduce macro generator/behavior 3 and a schema-2 macro parameter
variant containing target water. Preserve legacy invalidation and decoding. Implement an explicit
production entry before switching ordinary new-atlas dispatch. Select a versioned threshold
policy using the [contract's D1 evidence](production-contract.md), rather than treating the private
zero contour as the existing production shared-threshold algorithm.

### Option C — Reopen the construction family

If the fixed visual contract, supported control domain or production realization cannot be met,
retain failed evidence and author another bounded design investigation. Do not relax adopted
targets, silently reduce the public domain, or continue unbounded seed/template retries.

## Decision

**No final option is selected.** Option B is the proposed implementation boundary, conditional on
family selection and the closed decision register in [the contract](production-contract.md).
Option A remains operational. Option C is the explicit failure path.

The preferred realization hypothesis for investigation is a fixed zero boundary with separately
versioned classification/realization rules, because the selected private certificate proves that
boundary. This is not permission to reuse the odd-half-tick contour type for zero. D1 must resolve
sample ties, quantization, persisted contour representation and extraction survival, or reject
this hypothesis in favor of an explicitly bounded permitted contour. Its exact classification
version/schema tuple is a remaining decision, not an implementation detail to guess in C1.

If Option B is selected, water invalidation must be version-aware and include macro generation
for v3. Owner quotas and feature identities are fixed before placement. All positive land terms
remain paid and guarded. Production records retain the existing distinction between semantic
geography, generator provenance, user intent, decoration and disposable caches.

## Consequences

### Positive

- Makes the water dependency and legacy compatibility boundary explicit before code exists.
- Allows narrow compatibility, generation and adoption changes with independent evidence.
- Preserves failed investigations and prevents private diagnostics from becoming accepted data.

### Negative

- Water edits require new macro computation for v3, unlike legacy classification-only edits.
- The current private family does not demonstrate the entire public control domain or final
  visual acceptance; further bounded work may reject it.
- Zero-contour realization requires a reviewed treatment of ties and extraction, even if the
  production lattice and quantization scale remain unchanged.

### Neutral or follow-up

- Follow [D1–D3 and conditional C1–C3](child-plan.md); do not duplicate completed v2 compatibility.
- Macro owners remain transient construction identities; semantic features retain their own
  classifier/identity contract.
- Subsequent region context work remains separately scoped after accepted v3 geography.

## Compatibility and migration

The [exact current/proposed table](production-contract.md) is part of this proposal. Proposed
macro behavior/generator 3 and macro parameter schema 2 must agree with accepted provenance and
typed seeds. The v3 composition manifest must identify v3 output. Remaining classification,
realization and contour-schema decisions must be settled before this ADR can be accepted.

No migration of accepted v1/v2 samples, partitions, parameters or output hashes is proposed.
Reopen must invoke no generator and byte-stable reserialization must preserve the existing
contract. Unsupported future or mixed tuples fail clearly. Package/record versions, seed
derivation/stream algorithms, lattice IDs, semantic/coastline versions and parent-context
contracts retain their identities only while their actual contracts remain unchanged.

Changing a macro parameter schema does not by itself change the `.mapworld` package version.
If the required contour/provenance representation cannot fit an additive strict accepted-record
variant, stop and split a reviewed persistence design before C1. New canonical fixtures are
additive with explicit human review; old fixtures are not overwritten. Explicit later parent
replacement may stale child context but never silently regenerate child maps.

## Validation

Require human selection under the retained fixed visual contract, then an accepted successor
ADR with no unresolved compatibility tuple. C1 proves strict decoding/mixed-version rejection
and byte-stable generator-free v1/v2/v3 reopen. C2 proves production profiles, shared anchors,
quantization/extraction bounds, deterministic finite failure behavior and 128 additional ordinary
preview seeds with no placement/calibration failures under the selected production contract.

C3 proves the ordinary application workflow and the required production 12-default/6-control
human-reviewed PNG cohort. Cross-platform canonical field/classification/fixture evidence must
be produced on macOS and Linux; repeated runs on one OS are not that proof. See
[ADR-0029's validation boundary](../../adr/0029-separated-macro-landmass-field.md) and
[fixture conventions](../../07-fixture-conventions.md). Neither the 128-preview sweep nor the
private six-row comparison substitutes for full-profile, semantic or human evidence.

## Revisit conditions

Reopen this proposal when the fixed visual cohort fails, a public control cannot be realized
without an undocumented clamp, production contour extraction invalidates certificates, or a
required compatibility change exceeds the additive record boundary. New evidence must name the
failed hypothesis and retain its provenance; no selected targets or old records change silently.
